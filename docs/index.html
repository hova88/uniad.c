Architecture note · 2026.07

从像素到规划，
一条可检查的路径。

UniAD 不只是把五个任务放进同一张网络。它真正重要的设计，是让感知与预测以 query 为接口，沿着规划目标有方向地传递信息。

01

The thesis

关键不是「全栈」，
而是「面向规划」。

传统流水线逐级交付离散结果；普通多任务网络共享 backbone，随后各自离开。UniAD 选择第三条路：上游任务产生的表示继续进入下游，最后所有梯度都能围绕 ego planning 协调。

这改变了接口的含义。跟踪不只输出 3D 框，还提供带身份连续性的 agent query；在线地图不只输出折线，还提供 map query；运动预测在二者之间显式建模交互；占用预测把稀疏 agent 表示重新投回稠密空间；规划器最后读取自车、命令和环境风险。

核心判断UniAD 是有层级依赖的多任务系统，不是五个平行 head 的集合。
02

One frame, end to end

先看完整路径，
再拆每一个齿轮。

一帧由 6 个环视相机开始。图像 backbone 与 FPN 提取多尺度特征，BEVFormer 风格编码器结合相机标定，把透视图像组织成 200 × 200 × 256 的鸟瞰状态。

6 × image pyramid

六路 BGR 图像经 ResNet-101 与 FPN 形成多尺度相机特征；标定元数据决定每个 BEV query 应该从哪里采样。

03

Temporal BEV

世界状态不是一张图，
而是一段记忆。

当前 BEV query 同时读取多相机空间特征与上一帧 BEV。上一帧状态先按 ego motion 对齐，避免把自车移动误认为整个世界移动。空间交叉注意力解决“从哪些相机、哪些尺度取信息”；时序自注意力解决“过去保留什么”。

Bt=Encoder(Qbev, Fcam, Warp(Bt−1, Δpose))
坐标系所有下游任务在 ego-centric metric BEV 中交流；时间对齐发生在进入当前状态之前。
04

Five coupled modules

五个模块，
一组逐渐具体的查询。

点击模块可展开它读取什么、生成什么，以及为什么规划器需要它。箭头代表表示依赖，不代表简单的后处理顺序。

4.1 TrackFormer — 让物体跨帧保持身份

输入 BEV feature + 900 个初始 object queries + 延续的 track queries。

输出 动态数量的 agent features、位置、3D box、类别与速度。新 query 负责发现，存活 query 负责延续，避免每帧检测后再做独立关联。

4.2 MapFormer — 把静态几何变成可交流的 query

输入 BEV feature + 300 个 map queries。

输出 车道分隔、道路边界、人行横道等在线矢量化元素及其 map features。它们随后进入 MotionFormer，成为 agent 运动的几何约束。

4.3 MotionFormer — 交互，而不只是外推

输入 agent query、map query、agent position 与场景/agent 级轨迹 anchors。

过程 依次进行 agent–agent、agent–map、agent–goal 三类交互；每个 agent 保留 6 个未来模态。

输出 每个 agent 的 6 × 12 × 2 轨迹与概率，同时产生供占用和规划使用的 motion query。

4.4 OccFormer — 从稀疏参与者回到稠密风险场

输入 当前 BEV、按模态聚合的 motion query 与 agent feature。

过程 递归预测未来 BEV；pixel–agent interaction 把参与者信息写入低分辨率稠密特征，再解码到 200 × 200。

输出 未来 5 个时间步的 instance-level 与合并 occupancy。后者为规划提供不依赖类别的碰撞界面。

4.5 Planner — 把所有表示收束为 6 个点

输入 SDC query、导航 command、BEV 环境表示和未来 occupancy。

输出 未来 6 个 ego waypoints。学习到的轨迹先形成，再通过 occupancy-aware cost 约束碰撞风险；训练目标包含 imitation 与 collision 项。

05

Inside MotionFormer

一条未来不够，
交互才是预测的主体。

同一辆车可能直行、减速或转弯。UniAD 用场景级与 agent 级 anchors 初始化多模态 query，再依次聚合其他参与者、地图与目标点的信息。这里的关键不是“画出六条线”，而是每条线都在共享场景约束下被更新。

06

Sparse → dense → action

为什么既要轨迹，
又要占用？

轨迹适合表达已识别 agent 的意图；occupancy 适合表达“这块空间未来是否安全”，包括难以稳定分类或关联的区域。两种表示互补：MotionFormer 提供对象级解释，OccFormer 提供规划可直接查询的稠密风险。

07

Optimization

统一不等于
一次性训练。

完整系统分两阶段优化。第一阶段建立可靠的感知表示；第二阶段加入运动、占用和规划，并让各任务损失共同塑造共享查询。这样既控制显存，也避免随机初始化的下游目标过早扰动感知。

Stage 1Perception pretraining

TrackFormer + MapFormer
6 epochs · image backbone frozen

Stage 2Joint optimization

Motion + Occupancy + Planning
20 epochs · planning-oriented losses

Ltrack · focal + L1

Lmap · cls + mask + dice

Lmotion · multimodal trajectory

Locc · BCE + dice

Lplan · imitation + collision

L=Σ λtask Ltask

“planning-oriented” 并不表示只保留规划损失。恰恰相反，中间监督让查询保持可解释、可训练；规划目标负责决定这些任务为什么要彼此协作。

08

The C11 vertical slice

缩小数值，
保留表示流。

UniAD.c 不是把 Python 模型“改写成 C”的伪装。它是一个有边界的合成垂直切片：用固定容量、种子权重和标量算子，验证时序状态、查询选择、五个输出面与序列化契约。

一次 ua_infer 发生了什么

  1. 01

    Camera projection六路 3×8×8 平面按种子权重投影为 8×8×16 BEV。

  2. 02

    Temporal carry若 scene key 连续，整数 ego translation 对齐上一帧并以 .65/.35 混合。

  3. 03

    Spatial analogue中心与四邻域采样模拟局部空间聚合；结果成为下一帧 resident state。

  4. 04

    Query decode64 个 BEV cell 形成候选，stable top-k 固定选出 8 个 tracks；四条 map elements 同源解码。

  5. 05

    Future + action每个 track 生成 3×4 模态，三帧 occupancy，最后由 command 生成 6 点 plan 与 collision score。

故意缺失无真实 backbone、deformable attention、checkpoint 映射、yaw warp、数据集评估或完整 device-resident CUDA 图。

What remains

完整理解，
从承认缺口开始。
