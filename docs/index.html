How one query moves through perception, prediction, and planning—then becomes six ego coordinates over the next three seconds.

Subject: OpenDriveLab / UniAD Pinned revision: 609ee08 Reviewed: 2026-07-25

Abstract　UniAD's contribution is not merely placing detection, tracking, mapping, motion, occupancy, and planning inside one model. It redesigns the interfaces between them. Sparse entity queries flow through TrackFormer → MotionFormer → Planner, while dense BEV state flows through the encoder → OccFormer → Planner. The two paths meet at planning, turning perception and prediction from frozen upstream deliverables into a shared intermediate language optimized for the final objective.

Claim boundary

Production architecture comes from the paper, supplement, and pinned source.

Executable demo is a reduced synthetic C11 graph.

Not claimed: released-weight equivalence or nuScenes accuracy.

01 / The problem

The opening questionIf every module is accurate on its own benchmark, why can the final plan still be brittle?

Modular systems discard
what planning needs most.

A 3D box tells the next module where a car is, but compresses away most of the detector's beliefs about occlusion, context, and uncertainty. Information thins at every discrete interface; independently optimized modules can only pass their errors downstream.

Conventional multi-task learning reduces duplicated computation, but often shares only an image backbone. Detection, mapping, and prediction still terminate inside separate heads. UniAD asks a more precise question: if safe planning is the final objective, in what form should upstream knowledge remain available downstream?

The answer is the query. It is not a final prediction, but a 256-dimensional state with a wide receptive field that attention can continue to update. Agents, maps, and ego intent become queries; space and risk remain dense BEV fields. “What is visible,” “how it may move,” and “where it is unsafe to go” are no longer three unrelated answers.

Answer 01The failure is not only inaccurate modules. It is a lossy contract between them. UniAD keeps sparse beliefs and dense spatial evidence alive long enough for planning to interrogate both.

Not opaque end-to-end control

UniAD preserves explicit supervision for detection, mapping, trajectories, and occupancy. It unifies differentiable representations and objectives; it does not hide every intermediate task.

02 / System anatomy

Next questionIf queries are the language, who speaks to whom—and which information bypasses the conversation?

Six tasks relay
one frame forward.

At inference, six cameras first produce multi-scale image features; a BEV encoder transforms perspective views into a common ego-centric frame. TrackFormer and MapFormer read dynamic agents and static roads from the same BEV. MotionFormer jointly forecasts every participant, OccFormer projects those futures back into a dense grid, and Planner emits six waypoints.

It resembles a line but is actually a skip-connected directed graph. MapFormer does not enter Planner directly, yet changes ego intent through MotionFormer. MotionFormer emits both an ego query and agent dynamics for OccFormer. The original BEV bypasses every sparse decoder and remains directly available to Planner.

Answer 02There is no single relay baton. Sparse queries carry identity and intent; dense BEV carries geometry and risk. Planner deliberately receives both.

03 / The coordinate machine

The coordinate problemHow can a query ask “what is 18 meters ahead” when every camera measures only pixels?

BEV is not just a feature map.
It is the shared coordinate system.

Cameras see perspective projections; planning needs “18 meters forward, 2 meters left.” The BEVFormer encoder organizes evidence from six views into a 200 × 200 × 256 ego-centric grid.

Every BEV query corresponds to a location on the ground plane. Spatial Cross-Attention uses camera calibration to project reference points into cameras that can see them, then samples valid positions from four image-pyramid levels. Temporal Self-Attention reads the previous BEV after ego-motion alignment. The released configuration repeats both operations across six encoder layers.

Bt = Enc(Qbev, Fcam, Align(Bt−1, Δpose))

“Temporal” therefore involves two operations: align the past using CAN-bus translation and rotation, then attend between current and past queries. Without alignment, forward ego motion would look like the entire world moving backward.

Answer 03BEV turns six incompatible image planes into one metric memory. Calibration answers where to sample; ego-motion alignment answers where the previous evidence moved.

Spatial extent

The paper describes roughly [-51.2m, 51.2m]. The occupancy head uses 0.5m cells over [-50m, 50m]. Sampling boundaries are not identical across heads.

04 / TrackFormer

The identity problemIf detections are recomputed every frame, what prevents the same car from becoming a new object every 500 milliseconds?

The life of a track query.

TrackFormer solves detection and tracking together. Each frame receives fresh detection queries that search for first-time objects, while surviving track queries continue to model the same objects from the previous frame. Both read BEV, but identity is assigned differently.

A newborn query is paired with ground truth through Hungarian matching. An existing track query is not rematched; it inherits its previous ground-truth index. That inheritance is the source of identity continuity. After six decoder layers, a dynamic set of valid states forms Q_A ∈ RNa×256 and enters MotionFormer.

Answer 04Identity lives in query state, not in post-hoc box matching. Only newborns need assignment; surviving tracks carry their assignment across frames.

Two thresholds

At inference, newborn detection queries use 0.4 and track queries use 0.35. A low-scoring track is not immediately deleted; its lifecycle ends only after roughly two continuous seconds below threshold.

The one exceptional query

Beyond the 900 object queries, UniAD adds a dedicated ego-vehicle query. It does not participate in ordinary object matching, yet interacts with the scene through TrackFormer and MotionFormer like any other agent. By planning time, ego is no longer an external coordinate origin; it is a scene participant with state and future intent.

05 / MapFormer

The geometry problemA car is moving forward. Is that motion legal, likely, or already leaving the road?

The map is not a backdrop.
It constrains motion.

If MotionFormer knows only agents, it can extrapolate velocity but cannot know whether the space ahead is a lane, an intersection, or off-road. MapFormer turns road geometry into queries so agent–map interaction happens in feature space.

Adapted from Panoptic SegFormer, it divides the map into things and stuff. Three hundred thing queries represent instances such as lanes, boundaries, and pedestrian crossings; one class-fixed stuff query represents drivable area. Six location-decoder layers place elements, while mask decoders recover shape.

Every layer is supervised, but only final-layer thing queries Q_M enter MotionFormer. Map masks are outputs for humans and metrics; map queries are the interface consumed by downstream prediction.

Answer 05Velocity cannot decide. Map queries add lane topology, boundaries, crossings, and drivable surface before a trajectory is chosen.

Online map ≠ HD map

MapFormer estimates road elements online from current camera evidence and BEV, avoiding reliance on a pre-built map and exact map localization.

06 / MotionFormer

The forecasting problemWhy is extrapolating each agent independently wrong even when its current velocity is known?

The subject of prediction
is interaction, not trajectory.

MotionFormer maintains six modes per agent, each predicting twelve future points. These futures are not regressed from scratch. Training trajectories are grouped by class and clustered with k-means into local agent-level anchors, then rotated and translated by the current agent pose into scene-level anchors.

Every motion query has context and position components. Position is not one point but the sum of four priors:

Qpos= φ(Iscene) + φ(Iagent) + φ(x̂0) + φ(x̂Tl−1)

The first two terms encode dataset motion priors, the third binds the query to its current agent, and the fourth is the endpoint predicted by the previous layer. Each decoder layer therefore updates the goal and re-examines the environment around that new endpoint.

Answer 06A future is conditional: on other agents, on road geometry, and on evidence near the intended endpoint. MotionFormer computes all three conditions in parallel at every decoder layer.

Scene-centric

All agents are forecast once in a common scene frame; the system need not rotate the whole scene into each vehicle's local frame. In the paper's ablation, rotated scene anchors materially improve minADE and minFDE.

Two nonlinear optimizers that are easy to confuse

MotionFormer's nonlinear smoother operates only while preparing training targets. Upstream position and heading are imperfect; forcing the network to regress a ground-truth trajectory from the wrong start can create implausible curvature and acceleration. Targets are therefore smoothed under jerk, curvature, curvature-rate, acceleration, and lateral-acceleration costs. This process never runs at inference and is not Planner's obstacle-avoidance optimizer.

07 / OccFormer

The safety problemTrajectories say where recognized agents may go. What lets Planner ask whether one particular future cell is safe?

Write sparse participants
back into a dense future.

Trajectories describe agents that have already been recognized and associated. Planning asks a different question: will a future cell be safe to occupy? OccFormer combines agent identity with dense scene state, producing both instance-level occupancy and a merged risk field.

First, six motion modes are max-pooled over the mode dimension to form Q_X. It is concatenated with track query Q_A and position embedding P_A, then passed through a timestep-specific MLP to create agent feature Gt.

Gt=MLPt([QA, PA, maxk Qmotion])

Meanwhile, BEV is downsampled to 1/4 resolution; each temporal block goes to 1/8 resolution for pixel–agent interaction. The roles are reversed from a conventional object decoder: dense pixels are queries, while agent features are keys and values. A coarse instance mask restricts each pixel to its corresponding agent.

Answer 07OccFormer projects identity-aware sparse futures back into a dense field. Each cell can carry risk without forcing Planner to enumerate objects.

Time horizon

Five blocks mean the current frame plus four future frames. At 2Hz, occupancy covers two seconds; motion and planning both extend to three seconds.

08 / Planner

The decision problemOnce perception and prediction agree on the world, how does intent become six safe coordinates?

Six points inherit
every earlier representation.

Planner does not concatenate every task's decoded output. It reads three condensed representations: TrackFormer's ego query, MotionFormer's six ego motion queries, and one of three command embeddings—left, right, or forward. MLP encoding and max-pooling across modes produce one plan query.

That query cross-attends the full BEV through a three-layer transformer decoder. An MLP then regresses six 2D increments and cumulatively sums them into a three-second path. Sparse intent has now read the dense world again.

Qplan=maxmode MLP([Qego-track, Qego-motion, Ecommand])

Answer 08The command chooses a maneuver family, ego queries encode intent, BEV supplies scene context, and time-aligned occupancy can bend the learned reference away from risk.

Training vs. inference

Training uses imitation plus collision loss. Inference can additionally optimize the path against OccFormer's binary occupancy. These are distinct safety mechanisms.

How safety margin enters training

Collision loss checks more than ego's original bounding box. The paper uses three expansions against future agent boxes: (weight, expansion) = (1.0, 0m), (0.4, 0.5m), (0.1, 1m). Immediate collision receives the strongest penalty, while the outer buffer still contributes a weaker gradient.

09 / Learning

The optimization problemIf the architecture is unified, why not train every module from random initialization in one pass?

Unified training,
but not all at once.

The full graph has 125 million parameters and multiple sequence-heavy tasks. UniAD stabilizes optimization with two training stages and deliberately freezes its most expensive image and BEV components.

Answer 09Shared gradients are useful only after the coordinate system and sparse interfaces become stable. Stage 1 establishes perception; Stage 2 makes downstream objectives negotiate over those representations.

The full experiment uses batch size 1, five-frame training sequences, AdamW, learning rate 2×10⁻⁴, weight decay 10⁻², and sixteen A100 GPUs. The released stage-2 configuration sets queue length to 3; ablations also shorten sequences and epochs for efficiency. Full and ablation settings must not be conflated when interpreting results.

10 / What the evidence says

The scientific questionHow do we know the query chain contributes information rather than merely adding parameters?

What evidence supports
the unified design?

The most informative ablation is not the final leaderboard, but the dependency graph. Motion prediction improves with agent perception alone; adding the online map reduces minADE and minFDE further. OccFormer benefits from tracking and motion features beyond dense BEV. BEV attention, collision loss, and occupancy optimization each improve Planner.

The query chain is therefore more than code reuse. Each upstream task contributes structure a downstream task can exploit: maps constrain feasible motion, motion features help occupancy separate future instances, and occupancy provides planning with a class-agnostic safety surface.

Answer 10Ablations improve along the same dependency edges the architecture claims: map helps motion, motion helps occupancy, and occupancy-aware mechanisms help planning. The evidence is directional—not proof that every added parameter is equally valuable.

Metric conditions

Standard minADE and minFDE are computed only on successfully matched true positives. EPA and minFDE-AP are the metrics that jointly penalize perception and prediction failure.

Planning metrics still require care

UniAD evaluates open-loop future trajectories on nuScenes, not closed-loop driving. The repository also records two planning-L2 conventions: UniAD measures displacement at a specific future timestamp, while ST-P3/VAD commonly average up to that timestamp. Two values both called “3s L2” may not be the same statistic.

11 / UniAD.c

The evidence problemWhat can this repository actually prove—and can the reader inspect the exact result rather than trust a decorative rendering?

What remains,
and what is deliberately absent.

The C11 program in this repository is a representation-flow vertical slice, not a port of the released checkpoint. It reduces every tensor and uses deterministic scalar operators so state lifetime, input containers, and the result schema remain auditable.

12 / Correctness ladder

The final questionWhen does “the demo runs” become evidence that the production model has been reproduced?

Evidence climbs one rung
at a time.

The repository can establish safe container parsing, basic-operator agreement with an oracle, and correct temporal carry in a two-frame synthetic graph. None of those facts implies production-checkpoint equivalence or task accuracy on nuScenes.

Answer 12Only after export, operator coverage, tensor-by-tensor checkpoint comparison, and dataset evaluation. This repository intentionally stops three rungs earlier.
